# 사용자 시나리오

> PRD(`doc/2-PRD.md`)와 도메인 정의서(`doc/1-domain-definition.md`)를 기반으로, 개발 시 화면/API 구현 참고용으로 정상 흐름 + 예외 흐름을 정리한 문서다. 상세 비즈니스 규칙은 도메인 정의서 7장을 참고하고 여기서는 반복하지 않는다.
>
> 반응형 웹이므로 데스크톱/모바일 흐름은 동일하고 레이아웃만 다르다. 별도 시나리오로 구분하지 않는다.

---

## 공통: 회원가입 및 로그인

**액터**: 영양사, 취식자 (가입 전에는 역할 없음)

**사전조건**: 없음

**기본 흐름**
1. 회원가입 화면에서 이름, 이메일, 비밀번호, 역할(영양사/취식자)을 입력한다.
2. 가입 완료 후 이메일/비밀번호로 로그인한다.
3. 역할에 맞는 화면(영양사: 프로모션 관리 / 취식자: 프로모션 목록)으로 진입한다.

**예외/대안 흐름**
- 이미 가입된 이메일로 가입 시도 → 가입 실패, "이미 사용 중인 이메일" 안내.
- 잘못된 이메일/비밀번호로 로그인 시도 → 로그인 실패 안내.
- 로그아웃 후에는 로그인 화면으로 이동, 인증 필요 기능 접근 시 로그인 화면으로 리다이렉트.

---

## 영양사 시나리오

### 1. 프로모션 등록

**사전조건**: 영양사로 로그인한 상태

**기본 흐름**
1. 프로모션 등록 화면에서 제목, 내용, 신청 시작일/종료일, 진행일, 모집 인원을 입력한다.
2. 등록 버튼을 누르면 프로모션이 생성되고 취식자에게 목록에 노출된다.

**예외/대안 흐름**
- 진행일이 신청 종료일보다 이전인 경우 → 등록 실패, 유효성 오류 안내.
- 필수 항목 누락 시 → 등록 실패, 입력 항목별 오류 안내.

### 2. 프로모션 수정/삭제 (P1)

**사전조건**: 영양사로 로그인, 본인이 등록한 프로모션 존재

**기본 흐름**
1. 본인이 등록한 프로모션을 선택해 수정 화면으로 이동한다.
2. 내용을 수정하거나 삭제 버튼을 눌러 프로모션을 삭제한다.

**예외/대안 흐름**
- 다른 영양사가 등록한 프로모션 수정/삭제 시도 → 권한 없음으로 거부.
- 현재 신청 인원보다 적은 모집 인원으로 수정 시도(신청자 존재 시) → 수정 실패, "현재 신청 인원 미만으로 축소 불가" 안내.
- 신청자가 있는 프로모션 삭제 → 프로모션과 함께 해당 신청 기록도 cascade 삭제됨을 확인 화면에서 안내 후 삭제.

### 3. 신청 현황 및 신청자 목록 확인 (P1)

**사전조건**: 영양사로 로그인, 본인이 등록한 프로모션 존재

**기본 흐름**
1. 본인이 등록한 프로모션을 선택한다.
2. 현재 신청 인원과 신청자 목록(이름 등)을 확인한다.

**예외/대안 흐름**
- 다른 영양사가 등록한 프로모션의 신청 현황 조회 시도 → 권한 없음으로 거부(본인 등록 프로모션만 조회 가능).
- 신청자가 없는 경우 → "신청자 없음" 상태로 빈 목록 표시.

## 취식자 시나리오

### 1. 프로모션 목록/상세 조회

**사전조건**: 취식자로 로그인한 상태

**기본 흐름**
1. 프로모션 목록에서 제목, 신청 기간, 모집/신청 인원을 확인한다.
2. 프로모션을 선택해 상세 내용(설명, 진행일 등)을 확인한다.

**예외/대안 흐름**
- 등록된 프로모션이 없는 경우 → "등록된 프로모션 없음" 안내.

### 2. 프로모션 참가 신청

**사전조건**: 취식자로 로그인, 신청 가능한(기간 내, 정원 여유 있는) 프로모션 존재

**기본 흐름**
1. 프로모션 상세에서 신청 버튼을 누른다.
2. 로그인 사용자 정보로 신청이 등록되고 신청 완료 상태가 화면에 표시된다.

**예외/대안 흐름**
- 신청 종료일이 지난 프로모션 → 신청 버튼이 비활성화되어 애초에 클릭 불가.
- 이미 신청한 프로모션에 재신청 시도 → 서버에서 중복 신청 거부, "이미 신청함" 안내.
- 모집 인원이 마감된 시점(동시 신청 포함)에 신청 시도 → 서버 원자적 검증으로 거부, "정원 마감" 안내.

### 3. 신청 취소

**사전조건**: 취식자로 로그인, 본인의 신청 내역 존재

**기본 흐름**
1. 신청한 프로모션 상세 또는 내 신청 목록에서 취소 버튼을 누른다.
2. 신청이 삭제되고 신청 가능 상태로 화면이 갱신된다.

**예외/대안 흐름**
- 본인이 신청하지 않은 프로모션(또는 타인의 신청)을 취소 시도 → 권한 없음으로 거부.

## 시나리오 커버리지 요약

| 기능 | PRD 우선순위 | 정상 흐름 | 예외 흐름 |
| --- | --- | --- | --- |
| 회원가입/로그인/로그아웃 | P0 | O | 이메일 중복, 인증 실패 |
| 프로모션 등록 | P0 | O | 진행일 검증, 필수값 누락 |
| 프로모션 목록/상세 조회 | P0 | O | 목록 없음 |
| 참가 신청 | P0 | O | 마감 후 신청, 중복 신청, 정원 초과 |
| 신청 취소 | P0 | O | 타인 신청 취소 시도 |
| 프로모션 수정/삭제 | P1 | O | 타인 프로모션 수정 시도, 정원 축소 제한, 삭제 cascade |
| 신청 현황/신청자 목록 확인 | P1 | O | 타인 프로모션 조회 시도, 신청자 없음 |
