# 배포 프론트엔드 E2E 테스트 리포트

- 프론트엔드: `https://b2bpro-121-fe.vercel.app`
- 백엔드: `https://b2bpro-121-be.vercel.app`
- 방식: Playwright MCP로 실제 브라우저를 구동해 `docs/4-user-scenario.md` 기준 시나리오를 수동 시나리오 기반 E2E로 검증
- 결과: 전 시나리오 PASS (결함 없음)

## 사전 확인

- CORS: 백엔드가 `https://b2bpro-121-fe.vercel.app` origin의 preflight에 정상적으로 `Access-Control-Allow-Origin`을 반환함을 확인 (이전에 발견된 프론트/백엔드 도메인 오설정 이슈 해소됨).
- `vercel.json`의 SPA rewrite 덕분에 `/signup`, `/promotions/3` 등 클라이언트 라우트 직접 접근 시 404 없이 정상 렌더링됨.

## 커버하지 않은 항목

- 정원 축소 제한(신청 인원 미만으로 capacity 변경 시 400)은 폼의 `min=1` 제약 때문에 브라우저로 직접 재현 불가 — 백엔드 테스트(`applicationRoutes.test.js` 등 57건 전부 PASS)와 API 레벨 E2E(`e2e/api-e2e.js`, 34/34 PASS)로 이미 검증됨.
- 신청 종료일이 지난 프로모션의 "신청 마감" 비활성화, 존재하지 않는 프로모션에 대한 신청 등은 이전 로컬 E2E(`e2e/report.md`)에서 이미 검증되었고 이번 배포본에서 코드 변경이 없어 재검증 생략.
